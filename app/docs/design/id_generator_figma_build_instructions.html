1. Executive Summary

Build the new ID Generator page as a frontend-only job creator. The page should not attempt to edit PSD files directly. Instead, it creates a job in Supabase. A local Windows worker reads the job, runs Photoshop with a JSX script, exports the result, uploads it back to Supabase, and the website displays the final file. 

Figma-designed website
  → Custom Tools
    → Page 3: ID Generator
      → Create Supabase job
        → Local Windows worker claims job
          → Photoshop opens EmployeeID.psd
            → JSX updates text, images, smart objects, and fonts
              → Export PNG/PDF/PSD
                → Upload output to Supabase
                  → Website displays completed result
Executive decision: Use Supabase + local Node.js worker + Photoshop JSX. This is easier and more stable than a Figma plugin, webhook, ngrok server, UXP plugin, or browser-based PSD rendering.

2. Scope and Safety Rules

The page must be framed and designed as an internal company badge generator. It should not be positioned as a government ID, passport, driver license, travel document, bank KYC document, or official identity document generator.

Required product language: Use “Internal Company Badge”, “Employee Badge”, “Staff Card”, or “Access Badge” in helper text and descriptions. The navigation page name can remain ID Generator, but the visible page subtitle should clarify that it is for internal company badge generation.

Do not build these features

  • No official document templates.
  • No passport, national ID, driver license, visa, or government-document wording.
  • No MRZ generation or validation.
  • No fake security features, hologram simulation, perforation simulation, machine-readable official identifiers, or official seals.
  • No claims that the output is legally valid identification.

Allowed features

  • Internal employee badge generation.
  • Company branding, employee name, role, department, employee number, validity dates, photo, signature, QR code for internal systems, and export preview.
  • Local Photoshop automation for legitimate internal card production.

4. System Architecture

Frontend

Figma-designed web page. It uploads images, creates jobs, and displays job status.

Supabase

Stores job rows, input JSON, uploaded images, final outputs, logs, and status.

Local Worker

Runs on the Windows machine with Photoshop installed. Polls jobs and executes JSX.

Why this architecture is the most stable

  • No public port on the local computer.
  • No ngrok or temporary tunnel required.
  • No Figma plugin complexity for version 1.
  • Photoshop renders final files locally with the correct fonts installed.
  • Supabase handles database, storage, API access, and job status in one place.

9. Frontend Logic for the Figma Page

Frontend user flow

  1. User opens Custom Tools → ID Generator.
  2. User fills in employee badge fields.
  3. User uploads employee photo and optional signature.
  4. Frontend uploads assets to badge-inputs.
  5. Frontend creates a row in badge_jobs with status queued.
  6. Frontend starts polling that job row.
  7. When status becomes complete, show preview and download buttons.
  8. When status becomes failed, show a clean error message and job log.

Frontend pseudo-code

async function createBadgeJob(form) {
  validateForm(form);

  const photoPath = await uploadToSupabaseStorage("badge-inputs", form.employee_photo);
  const signaturePath = form.signature_image
    ? await uploadToSupabaseStorage("badge-inputs", form.signature_image)
    : null;

  const jobPayload = {
    template: "EmployeeID.psd",
    employee_name: form.employee_name,
    employee_id: form.employee_id,
    department: form.department,
    role: form.role,
    valid_from: form.valid_from,
    valid_until: form.valid_until,
    export_format: form.export_format || "png",
    assets: {
      employee_photo_path: photoPath,
      signature_image_path: signaturePath
    },
    meta: {
      created_from: "custom-tools/id-generator",
      intended_use: "internal_company_badge"
    }
  };

  const job = await supabase
    .from("badge_jobs")
    .insert({
      status: "queued",
      template: "EmployeeID.psd",
      input_json: jobPayload,
      employee_photo_path: photoPath,
      signature_image_path: signaturePath
    })
    .select()
    .single();

  return job.data;
}

Polling pseudo-code

async function pollJob(jobId) {
  const interval = setInterval(async () => {
    const job = await getBadgeJob(jobId);

    updateStatusUI(job.status);

    if (job.status === "complete") {
      clearInterval(interval);
      showOutput(job.output_png_path || job.output_pdf_path || job.output_psd_path);
    }

    if (job.status === "failed") {
      clearInterval(interval);
      showError(job.error_message);
    }
  }, 3000);
}

10. Local Windows Worker Logic

The local worker is a small Node.js process running on the Windows machine where Photoshop and all required fonts are installed.

Worker folder structure

C:/EmployeeBadgeAutomation/
├── worker.js
├── run_employeeid_job.jsx
├── templates/
│   └── EmployeeID.psd
├── fonts/
│   ├── RequiredFont-Regular.otf
│   └── RequiredFont-Bold.otf
├── jobs/
│   └── {job_id}/
│       ├── input.json
│       ├── photo.jpg
│       └── signature.png
└── output/
    └── {job_id}/
        ├── result.png
        ├── result.pdf
        └── result.psd

Worker flow

  1. Start worker on Windows.
  2. Connect to Supabase with service role key stored in local environment variables.
  3. Poll for first job where status is queued.
  4. Claim job by setting status to processing.
  5. Download input assets to a local job folder.
  6. Create local input.json.
  7. Run Photoshop JSX script.
  8. Upload exported file to Supabase Storage.
  9. Update job status to complete.
  10. If any error happens, set status to failed and save error_message.

Worker pseudo-code

while (true) {
  const job = await getNextQueuedJob();

  if (!job) {
    await sleep(3000);
    continue;
  }

  try {
    await markJobProcessing(job.id);

    await prepareLocalJobFolder(job);
    await downloadJobAssets(job);
    await writeInputJson(job);

    await runPhotoshopScript(job.id);

    const outputPath = await uploadOutputToSupabase(job.id);
    await markJobComplete(job.id, outputPath);
  } catch (error) {
    await markJobFailed(job.id, error.message);
  }
}

Why polling is preferred

  • No public webhook to your local PC.
  • No firewall changes.
  • No ngrok dependency.
  • Stable even if your local IP changes.
  • Easier to restart if Photoshop crashes.

11. Photoshop JSX Automation

Photoshop automation should be separated from the website and cloud logic. The JSX script only receives a local job folder and does Photoshop work.

JSX responsibilities

  • Open templates/EmployeeID.psd.
  • Read jobs/{job_id}/input.json.
  • Preflight required fonts.
  • Update main PSD text layers.
  • Open Smart Objects where needed.
  • Replace or place uploaded images into the right placeholder layers.
  • Save Smart Object contents.
  • Export final PNG/PDF/PSD.

12. Font Consistency Plan

The final export must be rendered by the local Photoshop worker only. Do not rely on the browser, Figma preview, or another user device for final typography.

Font rules

  • Install all required fonts on the local Photoshop machine.
  • Use exact PostScript font names in the JSX script.
  • Run font preflight before opening/exporting the PSD.
  • If a required font is missing, fail the job instead of exporting with placeholder fonts.
  • Force the correct font after every scripted text replacement.

Font manifest

{
  "required_fonts": [
    {
      "label": "PRIMARY_REGULAR",
      "postScriptName": "RequiredFont-Regular"
    },
    {
      "label": "PRIMARY_BOLD",
      "postScriptName": "RequiredFont-Bold"
    }
  ],
  "layer_font_map": {
    "EMPLOYEE_NAME": "PRIMARY_BOLD",
    "EMPLOYEE_ID": "PRIMARY_REGULAR",
    "DEPARTMENT": "PRIMARY_REGULAR",
    "ROLE": "PRIMARY_REGULAR"
  }
}

Font preflight behavior

Before job export:
1. Refresh Photoshop fonts
2. Build installed font map
3. Compare required PostScript names
4. If missing font exists:
   - stop job
   - set job status to failed
   - show exact missing font in error_message
5. If all fonts exist:
   - continue PSD generation

14. Error Handling

Common errors to show clearly

Error Cause User message
Missing font Required font is not installed on local Photoshop machine Generation stopped because a required font is missing.
Missing template EmployeeID.psd not found locally The local template file is missing on the worker machine.
Missing image Upload failed or worker could not download asset One of the uploaded images could not be downloaded.
Layer not found PSD layer name changed or mapping is wrong A required template layer could not be found.
Photoshop not responding Photoshop crashed, froze, or scripting timed out The local Photoshop worker did not complete the generation.

Retry logic

  • Allow retry only if job status is failed.
  • Retry should create a new job row or reset the existing job after clearing output paths.
  • Do not retry endlessly. Keep a maximum retry count of 2 or 3.
